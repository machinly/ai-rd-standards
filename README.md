# 一人公司研发工作方式

本仓库只维护一份正式研发约定：[WORKFLOW.md](WORKFLOW.md)。它仅在用户明确调用 `$opc-rd` 或明确要求使用本规范时启用；普通实现、调试、文档、审查、发布和部署继续使用任务本身最直接的工作方式。

## 三个判断

1. **是否明确启用本规范？** 否：直接完成任务，不加载后续流程。
2. **是否真的需要长期契约？** 只有长期产品/API/数据/AI/基础设施行为、跨会话恢复、多个重要验收条件或显著回滚风险，才使用一个 OpenSpec change。
3. **是否将产生真实高影响副作用？** 生产、客户数据、凭据、权限、资金、外部通信、删除或不可逆动作，在执行前说明目标、影响、验证与恢复，并取得当次明确授权。

跨文件、用户可见、使用 AI、任务耗时或工作具有创造性，都不能单独触发额外规格、计划、审查、Agent 或工具。

## 文件地图

- [WORKFLOW.md](WORKFLOW.md)：唯一正式规范。
- [skills/opc-rd/SKILL.md](skills/opc-rd/SKILL.md)：显式调用时使用的薄运行时入口。
- [可选技术栈偏好](skills/opc-rd/references/stack-defaults.md)：个人偏好，不是通用流程规则，项目或用户决定优先。
- [OpenSpec](openspec/README.md)：只保存确有长期契约价值的活动变更。

旧四分类十一项、规则账本、历史审查和实验状态不再构成活动入口；需要追溯时使用 Git 历史。

## 检查

运行：

    python tools/check_workflow.py .

检查器只验证入口、链接、内容预算、活动状态和退役边界，不检查固定中文措辞、规则 ID 数量或历史账本行数。
