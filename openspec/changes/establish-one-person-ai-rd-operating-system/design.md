# 设计：一人公司 AI 研发操作系统

## 设计决策

### 1. 用 OpenSpec 作为流程主干

所有非微小变更都使用 OpenSpec artifacts，因为它们能跨越聊天上下文丢失，并给 AI agent 一个稳定事实来源。

### 2. 把人的注意力当成稀缺资源

默认实现细节应由仓库规范、官方文档和技术偏好决定。只有产品方向、资金、数据、合规、安全或长期架构后果明显的事项才升级给人判断。

### 3. 用两轮 review 替代大清单

每段内容只做两轮 review：

- Review A：一人可执行性和认知负担。
- Review B：产品、工程、可靠性、安全和回滚风险。

### 4. 把 AI 行为当成可测试的产品行为

任何用户可见 AI 变更，都必须在生产 prompt/model 变化前有最小 eval。prompt builder 必须进入代码或配置，不能只留在聊天记录里。

### 5. 后续规范按操作面拆开

后续 change 应分别处理：

- Go/Kratos/sqlc/gRPC 服务模板。
- Vite 前端与 Vercel 风格设计 token。
- AI prompt/eval 工作流。
- SRE-lite 运维。
- 发布与事故处理。

## 取舍

- 编码前多一个小计划步骤，但能减少返工和上下文丢失。
- 本阶段故意不展开所有实现模板，避免第一阶段过重。
- 默认一次只推进一个 active change，可能牺牲并行探索，但保护一人公司的专注力。
