# 产品设计

## 分类目的与边界

产品设计把已经选择的问题和结果转化为用户行为、范围、验收、信任和风险边界，并把这些决定组织成用户能够理解、完成、纠正和退出的体验。Explore / UX Prototype 用于比较关键流程与可理解性；Deliver 的 formal visual UX 用于形成生产性实现输入。它不选择系统结构、工程排期或发布方式。

## 根本原则

- **CATEGORY-PRODUCT-DESIGN-001**：产品设计应明确改变与不改变的行为；涉及用户界面请求时，还应覆盖等待、空缺、失败和成功状态。

## 包含的项目

- [定义](03-definition.md)：确定用户行为、范围、验收、指标、风险和退出边界。
- [体验设计](04-experience-design.md)：把已定义行为组织为完整、可访问、可信且可纠正的任务路径；Explore 可形成静态或可运行 UX Prototype，Deliver 适用时形成 formal visual UX 并取得开发前人工确认。

## 项目之间的关系

定义先说明本轮改变与不改变什么，并确定必须由人承担的高影响决定。关键流程或可理解性仍未知时，体验设计用 UX Prototype 尽快从真实产品入口 showcase；只有人选择的最小稳定行为 promote 后，才从转换点判断 Deliver formal visual UX。若交互推演暴露范围、承诺或风险缺口，则回到定义更新，而不是在界面中静默改变产品含义。

## 进入条件

选题已确认值得投入且已有足够问题证据时进入定义。工作涉及用户界面、交互状态、可访问性、自动化披露、信任、高风险确认或用户控制时进入体验设计；纯内部且不改变用户行为的工作只处理其真实触发项。

## 结束或循环条件

Explore 可以 valid、invalidated、revise、stopped 或 promote 结束；Prototype 本身不表示可交付。Deliver 在用户行为、非范围、验收与退出条件明确，关键任务路径及其异常、可访问和高影响控制边界完整，且适用的 formal visual UX 已由人确认时，可交给工程交付。任何后续证据推翻目标、用户场景、承诺或体验前提时，返回定义或体验设计重新判断。

## 与其他分类的接口

从立项接收已选择的问题、证据和投入边界；向工程交付提供稳定的产品行为、体验契约、适用的已批准可视 UX、验收和风险边界。工程验证或运行评估发现行为不成立、用户无法完成任务或信任边界被破坏时，把证据退回对应项目，而不是由下游自行重写产品决定。
