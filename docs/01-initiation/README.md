# 立项

## 分类目的与边界

立项决定一个事项是否值得占用有限容量，以及在承诺交付前还需要降低哪些关键不确定性。它覆盖候选比较、投入取舍、问题证据、调研和学习结论；不定义最终产品行为，也不代替体验、工程、发布或运行判断。

## 根本原则

- **CATEGORY-INITIATION-001**：立项要求选题建立在真实问题、义务或风险上；实验结果出来后，必须由人选择继续、停止、转向或迭代，不能继续凭感觉推进。

## 包含的项目

- [选题](01-topic-selection.md)：比较候选、约束在制投入并决定继续、让位、停车或结束。
- [调研](02-research.md)：用真实证据和受控学习降低一个明确决策的不确定性。

## 项目之间的关系

选题先判断问题、义务或风险是否值得占用容量。证据不足但值得继续了解时进入调研；调研围绕单一主要结果形成证据结论后回到选题，由选题决定继续投入、补证据、转向、推迟或结束。调研不自行承诺交付，选题也不以直觉替代所需证据。

## 进入条件

出现新的用户问题、商业机会、义务、风险、事故后续或维护需求，且需要与其他候选争夺容量时进入选题；已选问题的真实性、用户场景、价值指标或学习结论仍不足以支持投入决定时进入调研。

## 结束或循环条件

当事项被明确结束、推迟或停车时，本轮立项结束；当证据足以支持继续且投入取舍成立时，进入产品设计。调研产生新证据后必须回到选题重新判断，后续分类产生的新事实也可重新开启这一循环。

## 与其他分类的接口

向产品设计交付已选择的问题、目标结果、证据、投入边界与未决风险。产品设计或工程交付若发现前提不成立，应分别把问题定义或投入取舍退回本分类。运行维护中的反馈、指标、事故和质量信号经评估形成结论后，也回到选题或调研重新决策。
