# 工程交付

## 分类目的与边界

工程交付把已批准的产品行为、体验契约和风险边界转化为可运行、可验证且可安全暴露的技术结果。它覆盖技术结构、工作安排、实现、验证和发布；不重新决定产品价值与承诺，也不把生产运行和长期学习复制成发布前流程。

## 根本原则

- **CATEGORY-ENGINEERING-001**：工程交付不为假想规模引入复杂架构；实现需要改变既定边界时返回技术设计，发布默认小批量且可回滚。

## 包含的项目

- [技术设计](05-technical-design.md)：确定职责、所有权、依赖、契约以及副作用和恢复边界。
- [计划](06-planning.md)：为跨会话、独立验收或中断恢复困难的工作提供显式跟踪；一份记录足够时不再拆分。
- [实现](07-implementation.md)：在已批准边界内生成代码、配置、数据变更和其他技术产物。
- [验证](08-verification.md)：用与行为和风险匹配的证据判断约束是否真实成立。
- [发布](09-release.md)：基于当前证据控制真实环境、客户范围和外部表述面的暴露。

## 项目之间的关系

技术设计把产品输入转成系统边界与契约，计划据此组织工作，实现只落实已批准决定，验证用真实证据检查行为与风险，发布再根据当前证据决定暴露范围。任何项目发现上游输入不足或被推翻时，都返回拥有该决定的项目；不得通过下游补丁掩盖边界缺口。

## 进入条件

产品行为、体验和风险输入已足以选择技术方案时进入技术设计；工作跨会话、需要独立验收或中断后难以恢复上下文时形成显式计划；输入稳定后进入实现。实现产物需要证明行为和风险时进入验证，只有验证结论和发布边界仍有效时才进入发布。

## 结束或循环条件

发布被停止、延后或完成并完成结果观察与交接时，本轮工程交付结束。实现或验证失败返回相应上游，发布观察触发回退时回到发布、实现或设计；真实环境产生的新事实则进入运行维护，形成下一轮判断。

## 与其他分类的接口

从产品设计接收产品行为、体验契约、验收和风险边界；若这些前提不完整，退回产品设计或立项。发布后向运行维护交付实际暴露范围、可观察信号、停止与恢复边界以及未决风险。运行维护发现缺陷、质量回归或新约束时，经评估返回本分类的相应项目。
